# Day 01 — Define the Organization and Security Scope

**Goal:** Establish a defensible starting point for governance, risk, and compliance activities at a fictional DoD contractor.

## Key question

**What information, people, processes, technology, and external dependencies are within the security program's scope?**

## Deliverables

1. [Organization profile](01-Organization-Profile.md)
2. [ISMS and CUI environment scope statement](02-Scope-Statement.md)
3. [System boundary and data-flow diagram](03-System-Boundary.md)
4. [Stakeholder/RACI matrix](04-Stakeholders-RACI.md)
5. [Assumptions and open decisions](05-Assumptions-and-Decisions.md)

## Day 1 outcome

A **proposed** CUI environment boundary and ISMS scope, suitable for validation with a fictional executive sponsor, IT lead, contracts lead, and security lead. It is not a verified system security plan (SSP), a complete CUI asset inventory, or a compliance determination.

## Next step

Day 2 will validate these assumptions through asset inventory, CUI flow tracing, ownership, and classification.
