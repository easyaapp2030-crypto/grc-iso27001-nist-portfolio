# Day 05 — Security Policies & Procedures

**10-Day GRC Portfolio | Sentinel Defense Solutions (SDS)**

## Purpose
Translate the Day 3 simulated risks and Day 4 proposed security controls into practical, reviewable governance documents for a fictional 100-person DoD contractor handling simulated CUI.

## Deliverables
- `Information_Security_Policy.md` — organization-level governance policy
- `Access_Control_Procedure.md` — operational IAM and access lifecycle steps
- `Incident_Response_Procedure.md` — reporting, triage, escalation, containment, and recovery
- `Policy_Control_Traceability.csv` — draft linkages to NIST SP 800-53 Rev. 5 and CMMC/NIST SP 800-171 Rev. 2 identifiers
- `Approval_and_Review_Register.csv` — simulated approval workflow and review cadence

## How to use
1. Read the policies and procedures as **drafts**, not approved SDS policy.
2. Validate roles, actual system boundary, contract requirements, and Day 3 risk IDs before adoption.
3. Review Day 4 mappings and reconcile the draft traceability file with the actual control matrix.
4. Assign policy owners, request approval, and collect implementation evidence in later project days.

## Important scope and version note
This is an educational simulation; no real CUI, assessed implementation, or CMMC certification is claimed. NIST SP 800-171 Rev. 2 IDs are shown for illustrative CMMC Level 2 alignment; NIST SP 800-171 Rev. 3 uses different identifiers and contract applicability must be confirmed. Mapping is not evidence of implementation.
