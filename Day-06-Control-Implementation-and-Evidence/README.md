# Day 6 — Control Implementation & Evidence Collection

**10-Day GRC Portfolio Project | Sentinel Defense Solutions (SDS)**

> **Simulation notice:** All assets, personnel roles, implementation states, and evidence examples are fictional. No live DoD environment or verified CMMC compliance is represented.

## Objective
Demonstrate how a GRC practitioner moves from documented policies and selected controls to an evidence-based implementation assessment. This exercise builds on Day 4 control mapping and Day 5 policies and procedures.

## Deliverables
| File | Purpose |
| --- | --- |
| `Control_Implementation_Tracker.csv` | Control owners, implementation states, gaps, and planned actions |
| `Evidence_Collection_Register.csv` | Evidence requests, expected artifacts, review criteria, and collection states |
| `Evidence_Collection_Procedure.md` | Repeatable evidence request, review, handling, and retention workflow |
| `Control_Assessment_Summary.md` | Simulated assessment approach, observations, and next steps |
| `README.md` | Project explanation and navigation |

## Workflow
1. Define scope and identify the applicable control requirements.
2. Ask the control owner to explain the implemented safeguard.
3. Request evidence and validate its source, currency, completeness, and relevance.
4. Record implementation and evidence status separately.
5. Escalate gaps to a corrective-action/POA&M workflow.

## Framework references
- NIST SP 800-53 Rev. 5 — security and privacy control catalog.
- NIST SP 800-171 Rev. 2 — historical control identifiers used in the preceding project artifacts; **verify current revision applicability before real use**.
- CMMC Level 2 — cross-references in this exercise use the 800-171 Rev. 2-based assessment requirement IDs.
- ISO/IEC 27001:2022 Annex A — illustrative alignment, not a one-to-one equivalence.

**Important:** Mappings are educational starting points requiring independent validation against authoritative framework text and actual system scope. Evidence is *requested/not collected*; nothing here is presented as tested or compliant.

## Leadership takeaway
A policy or control statement alone is not proof of operating effectiveness. Defensible assurance depends on evidence quality, repeatability, ownership, and follow-through.
